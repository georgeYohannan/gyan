# Decisions

- 2026-11-16: Gyan is dark navy only. There is no light mode in version 1. Colors, fonts, and motion live in src/constants/theme.ts and are repeated in tailwind.config.js (a test keeps them in sync).
- 2026-11-16: Quiet body text color is #94A3B8. It is not in CLAUDE.md. It was chosen because it keeps 4.5:1 contrast on the navy background.
- 2026-11-16: The Supabase project with ref ofnspnobzesxmyqjxzad is the TEST project. Do not use it as live. Only the public key goes in the app (in .env.local), never the service_role key.
- 2026-11-16: Added status text colors that are not in CLAUDE.md: green #86EFAC (Ready) and soft red #FCA5A5 (Failed and errors). Both pass 4.5:1 on navy. White text on the orange record button (#C2410C) also passes 4.5:1. Brand blue is still never used as text.
- 2026-11-16: The help panel is a side panel on web windows 768 points wide or more, and slides up from the bottom on phones and narrow windows. All help words live in src/content/help.ts.
- 2026-11-16: /design is a builders-only page. On web it has a route but no tab button. On phones it is a "Design" tab that only appears in development builds (__DEV__), never in store builds.
- 2026-11-16: Google sign in is NOT in this step. Version 1 starts with email and password. Google needs a Google Cloud project and separate keys for web, iPhone, and Android, so it comes in its own later step. The product spec still lists it for version 1.
- 2026-11-16: The chunks table (search pieces of transcript) is not created yet. It needs a vector size, which depends on the embedding model, and that is still an open decision.
- 2026-11-16: The private file storage bucket and its rules are not created yet. No file upload exists yet. They come with the Upload feature.
- 2026-11-16: Row Level Security: the app can read only; server functions write. Members can read invites. Only owners read integrations (they may hold tokens). The app can change only display_name and preferred_language on a profile, so is_admin can never be changed from the app.
- 2026-11-16: Sign up trigger (public.handle_new_user) makes the profile, a Free-plan account, and the owner row in one step, and looks the plan up by name from the plans table. Passwords need at least 8 characters.
- 2026-11-16: The first-sign-in consent note is remembered per person on that device (not in the database). The wording needs a lawyer's review before public launch.
- 2026-11-16: The Design tab is removed from phones. The /design page still exists as a builders-only page you can open by typing its address on web. This replaces the earlier decision to show a Design tab in development builds.
- 2026-11-16: Upload size is capped at 50 MB per file, the Supabase Free plan limit (checked in the current docs). Founder chose to take the audio out of videos before upload instead of upgrading. This is built for the web (decoded in the browser, saved as a 16 kHz mono MP3 at 32 kbps, about 14 MB per hour). On phones it is not built yet: videos up to 50 MB upload as they are, bigger ones are refused with a friendly message. Phone extraction needs a native library and a development build.
- 2026-11-16: The MP3 maker is @breezystack/lamejs, which has an LGPL license. A lawyer should confirm it is fine for the paid product before public launch.
- 2026-11-16: The app still cannot write to the meetings table. It uses 4 database functions: create_note, mark_note_queued, mark_note_failed, restart_note_upload. They check the person belongs to the account. create_note refuses uploads when the plan limit is reached (limit read from the plans table). Files go in the private bucket notes-files at account id / note id / file name.
- 2026-11-16: Pasted text and uploaded text files are saved as source "text". They never count toward the monthly limit, so they are allowed even when the limit is reached. At the limit, Upload is blocked and Paste text still works. Notes count only when Ready (a later step).
- 2026-11-16: New note is opened from the Home button. It has no tab button of its own.
- 2026-11-16: Help entries can now have short lists under the sentences (used for statuses, file types, and the limit).
- 2026-11-17: Deepgram settings: model nova-3, diarize_model=latest (speaker labels; the old diarize=true is deprecated), detect_language=true, utterances=true, smart_format=true. The audio goes to Deepgram as a 10 minute private link, not as bytes through our function. Speakers are saved as "Speaker 1", "Speaker 2".
- 2026-11-17: Deepgram cost in ai_usage uses $0.0052 per minute (Nova-3 multilingual, the higher price, from deepgram.com/pricing). Speaker labels cost nothing extra. The rate is in supabase/functions/transcribe/settings.ts. It is a vendor cost, not a plan price, so it is not in the plans table.
- 2026-11-17: The Deepgram key is the server secret DEEPGRAM_API_KEY (set with supabase secrets set). In .env.local it is named EXPO_DEEPGRAM_KEY, only so you can copy it into the secret. The app never reads it.
- 2026-11-17: 3 server-only database functions (claim_transcription, finish_transcription, fail_transcription) do the status changes. Only the server key can run them. "Ready" and the +1 to the monthly count happen in one database step with the ai_usage row. A failed note never counts. Retry of a Failed note is allowed (it checks the plan limit again).
- 2026-11-17: Supabase Free server functions stop after 150 seconds, so very long recordings (about an hour or more) may end as Failed. Later options: Deepgram's callback option, or a paid Supabase plan. A note can also stay on Transcribing if the server stops halfway. An automatic rescue is not built yet.
- 2026-11-17: Pasted text and text files have no audio, so they get no transcript step. Note pages open from the Home list at /note/<id> and have no tab button.
- 2026-11-17: The current Supabase project stays the TEST project for good. For going live, the founder will set up a NEW paid Supabase project (new keys, new secrets, migrations and functions pushed again). Nothing live shares data with the test project.
- 2026-11-17: Screens opened from Home (New note, a note page) now live in a Stack inside the Home tab (src/app/(app)/(home)/). They were "hidden tabs" before, which Expo says cannot be navigated to, so on iPhone the New note screen flashed and bounced back. Web addresses are unchanged (/, /new-note, /note/<id>).
- 2026-11-18: The summary and action items are written by Claude Sonnet 5.5. It was chosen because it is good at meeting notes, it can be forced to answer in a strict shape (so the app always gets readable data), and it costs about half of the Opus model. About 4 to 6 cents for a 1 hour meeting ($2 per million tokens in, $10 per million out, checked 2026-11-17). The model name, the thinking effort ('low'), and the prices live in supabase/functions/summarize/settings.ts. To change model, change that one line.
- 2026-11-18: Anthropic's Workload Identity Federation (short-lived tokens instead of an API key) cannot be used with Supabase server functions today. Federation needs the workload to get a signed OIDC token from a provider it runs (AWS, Google Cloud, Azure, Kubernetes, GitHub Actions, SPIFFE or Okta). Supabase gives functions no such token and publishes no signing keys for them. So Gyan uses an API key kept as the Supabase server secret ANTHROPIC_API_KEY. Revisit federation before public launch. Keep a separate key for test and for live, and set a monthly spend limit in the Claude Console.
- 2026-11-18: A meeting now counts (+1 for the month) only when the note becomes Ready, not when the transcript finishes. Two new columns on meetings do this: counted_at (stamped the first time it counts, so Regenerate never counts twice) and summary_started_at (a lock, so two taps cannot pay for two summaries, and a stuck note can be picked up again after 3 minutes). A note that fails at any step never counts.
- 2026-11-18: The monthly meeting limit counts every source the same way: 1 uploaded recording, 1 phone recording, or 1 bot meeting each count as 1. Pasted text and uploaded text files never count, and they still work when the limit is reached. This confirms the "Confirm" row in docs/product-spec.md.
- 2026-11-18: Recap emails go to whoever the account owner picks: the owner only, the team members, or both. The default is the owner only, so nobody is emailed without the owner deciding it. The choice is saved per account in the integrations table and can be changed at any time. (The email feature itself is a later step.)
- 2026-11-18: The meeting bot is built behind a feature switch that stays OFF until a lawyer has reviewed the consent wording. Nobody can send a bot to a call until the switch is turned on. This matches the rule that Gyan never records or joins a meeting without a clear consent notice.
- 2026-11-18: If a transcript were ever too long for one request, the note fails with a plain message and no text is ever cut off quietly. Chunking is NOT built, because Claude Sonnet 5.5 holds about 1,000,000 tokens (roughly 100 hours of talking) and no realistic meeting comes close. The guard is MAX_INPUT_TOKENS in supabase/functions/summarize/settings.ts. If it is ever needed, the plan is: split the transcript at speaker turns into parts of about 20 minutes, summarize each part, then summarize the summaries into one, and log every call in ai_usage.
- 2026-11-18: A bad answer from the AI is tried exactly once more, then the note fails with a plain message. Both tries are paid for, so both are added into the one ai_usage cost row.
- 2026-11-18: Browser test scripts live in tests/ and are run with `npm run e2e` (@playwright/test). They answer every Supabase and AI call with fake data (tests/fixtures/fake-api.ts), so they cost nothing, need no account, and never touch real data. They check the interface, not the real services. The real end to end check, with the real AI, is the hand checklist in docs/testing/prompt-6.md. The scripts start the web app with `expo start --web --clear`, because a bundle left over from before new files were added gives a "Requiring unknown module" error.
- 2026-11-18: The side chat answers **all at once**, not word by word. Founder's choice: a streamed answer is nicer to watch but is more code and one more thing to break, and the whole answer arrives in 5 to 10 seconds anyway. The `chat` server function waits for Claude and returns the finished answer in one reply, well inside Supabase's 150 second limit. If streaming is wanted later, it is a change to 1 function and 1 panel.
- 2026-11-18: On a wide web window the chat **floats over** the note from the right, exactly like the help panel. Founder's choice: it reuses a pattern that already works instead of rebuilding the page as 2 columns. Tapping a passage number closes the chat so the highlighted transcript line is in plain view. On a phone it slides up from the bottom. The chat is drawn as a pop-up layer (a Modal), not as a box inside the page, because the bar at the top of the web app is drawn over anything inside the page.
- 2026-11-18: The side chat sends the **whole transcript as numbered passages**, not the closest pieces found by a search. docs/data-model.md describes the search version, which needs the `chunks` table and an embedding model. Neither exists, and for a chat about 1 note the search is not needed: a 1 hour meeting is a small fraction of what the model can hold. Passage 1 is the first transcript line, passage 2 the second, and so on. The embedding decision stays open for the all-notes chat and the Search screen.
- 2026-11-18: The daily chat limit is a column on the plans table, `chat_messages_per_day`, one number per plan, so it is set by the subscription and an admin can change it with no new code. The Free plan starts at 20 questions a day (about 15 cents a day per person at worst). The day starts at midnight UTC, the same as the monthly meeting count. Never hard code this number.
- 2026-11-18: A chat is **more private than a note**. Notes are shared with everyone on the account, but a chat can only ever be read by the person who asked. This narrows the earlier rule (any account member could read any thread). It is done in `private.can_read_thread` and the "Read own chat threads" rule.
- 2026-11-18: A question is saved before the answer is asked for, and the daily limit is checked in the same database step, so two fast taps can never slip past the limit. If the answer then goes wrong, **Retry re-uses the question that is already saved** (`claim_chat_retry`), so a problem never costs somebody a second question out of their day.
- 2026-11-18: The chat has its own settings file, `supabase/functions/chat/settings.ts`, separate from the summary's. It starts on the same model (Claude Sonnet 5.5) and the same 'low' thinking effort, because answering from passages that are right in front of the model is reading work. Keeping it separate means the chat can be tuned or moved to another model without touching summaries. The transcript is marked as worth remembering between questions (prompt caching), so follow-up questions about the same note cost about a tenth as much to read it again.
- 2026-11-18: Chat answers must cite a passage number for each fact, and must say "I could not find that in your notes." when the answer is not there. A number that points at no real line is dropped before it reaches the screen, so a link can never be dead.
